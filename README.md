# 四足机器人 Locomotion 强化学习训练（MuJoCo Ant + PPO）

> **一句话结论**：在纯 CPU 的笔记本上跑通「四足机器人 PPO 步态训练」完整闭环，
> 120 万步训练后策略可稳定行走 **12 秒 / 22.8 米，平均速度 1.9 m/s**；
> 过程中系统性地做了 4 版**奖励设计迭代**，定位并解决了「站立局部最优」与「扑街式前进」两类典型失败模式。

## 三、奖励设计迭代（核心内容）

这是整个项目最有价值的部分：**我按"速度跟踪"的目标自己设计奖励，连续 4 版都失败了，最后用对照实验定位原因**。

| 版本 | 奖励构成 | 结果 | 诊断 |
|---|---|---|---|
| v1 | 存活 1.0 + 高斯跟踪 2.0 | ep_len 满 1001，**vx ≈ 0**，track 0.03 | **站立局部最优**：不动也能拿 ~1.0/步，走路收益不显著 |
| v2 | 存活 1.0 + 前进 1.5 + 跟踪 2.0 | vx 1.3-1.7，但 **ep_len 仅 30-90** | **扑街式前进**：策略发现"摔倒前冲"能刷前进分，不摔倒的长期收益被低估 |
| v2b | 存活 **2.5** + 前进 1.0 + 直立 0.5 | ep_len 941，**vx 降到 0.19** | 存活权重过高，再次压倒一切 → **回到站立** |
| v3 | 存活 1.0 + 前进 **2.0** + 跟踪 **2.0** + 直立 1.0 | 中段 vx 0.54，最终 **vx -0.09** | 仍收敛到站立；说明**只调权重解决不了**，问题在结构 |
| **对照** | **原生 Ant-v5 奖励** | **return 1172，vx 1.9，ep_len 672，持续行走** | 证明 PPO 实现没问题，是**自定义奖励的线性前进项与存活项存在激励冲突** |

**关键结论**：
1. 四足 locomotion 里，"存活奖励"和"移动奖励"是竞争关系，权重消长会直接决定策略落在"站"还是"走"；
2. 用**线性速度项**做前进激励时，策略倾向于用不稳定姿势刷分（exploit），而不是学出稳定步态；
3. Gymnasium Ant 的原生奖励（含 contact、survival、control 多项 shaping）是**经过验证的配方**，先用它跑通闭环、再在其基础上做速度跟踪改造，是更工程化的路径；
4. **对照实验（控制变量）是排查 RL 训练问题最有效的手段**——在怀疑自己的实现之前，先用已知能收敛的配置跑一遍。

## 四、技术实现要点

- **向量化采样**：`SyncVectorEnv` × 16 环境，rollout 256 步，minibatch 1024；
- **PPO**：clip=0.2、γ=0.99、λ=0.95（GAE）、entropy 0、Adam lr=3e-4；
- **网络**：actor/critic 各 2×256 tanh，actor 末层正交初始化 std=0.01，log_std 可学习；
- **稳定训练**：advantage 归一化、梯度裁剪 max_norm=0.5、value loss 系数 0.5；
- **渲染**：`mujoco.Renderer` + `MjvCamera(mjCAMERA_TRACKING)` 跟随 torso，避免机器人跑出画面；
- **性能**：CPU（19 线程）约 1.0-2.0k steps/s，120 万步约 20 分钟。

## 六、下一步（把"能走"变成"可调速"）

当前策略跑的是 Ant 原生奖励，**还不能按指令速度走**。要让"速度跟踪"真正成立：

1. 在原生奖励基础上**加一项速度跟踪 shaping**（而不是替换掉原生奖励），小权重起步（0.5），逐轮加到 2.0；
2. 引入**课程学习**：v_target 0.3 → 0.6 → 1.0 → 1.5 m/s，每个阶段训练到稳定再提升；
3. 用 **asymmetric actor-critic**（critic 看特权信息如接触力、真实摩擦）提升样本效率；
4. 加入地形随机化与外力扰动，验证鲁棒性；
5. 有条件时（云端 GPU）把同一套配置迁移到 Isaac Lab，对比 sim2sim 差异。
